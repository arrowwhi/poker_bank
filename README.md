# Poker Bank Bot

Telegram-бот для управления банком на домашних покерных играх. Ведёт учёт покупок фишек, рибаев и кэш-аутов, а по итогам игры рассчитывает оптимальный план расчётов с минимальным числом переводов.

## Возможности

- Управление жизненным циклом игры: старт, завершение, отмена
- Заявки игроков (вход, рибай, выход) с подтверждением от дилера
- Прямые команды дилера без ожидания подтверждения
- Откат последних операций (`/undo`)
- Просмотр текущего состояния банка и участников
- История прошедших игр и персональная статистика
- Расчёт плана взаиморасчётов с минимизацией числа переводов
- Обработка расхождений банка при принудительном завершении

## Стек

- **Go 1.25**
- **PostgreSQL 15** — хранение всех данных
- **telebot.v3** — Telegram Bot API
- **pgx v5** — драйвер PostgreSQL
- **goose** — миграции базы данных
- **uber/zap** — структурированное логирование
- **Docker + Docker Compose** — окружение разработки и продакшн

## Быстрый старт

### Требования

- Docker и Docker Compose
- Telegram Bot Token от [@BotFather](https://t.me/BotFather)

### Запуск

```bash
# Скопировать конфиг
cp .env.example .env
# Заполнить TELEGRAM_TOKEN в .env

# Запустить в режиме разработки (PostgreSQL + hot-reload)
make dev
```

### Сборка без Docker

```bash
make build
# Бинарник: ./tmp/bot

export TELEGRAM_TOKEN=your_token
export DATABASE_URL=postgres://poker:poker@localhost:5432/poker_bank?sslmode=disable
./tmp/bot
```

## Команды

### Для всех участников

| Команда | Описание |
|---|---|
| `/start` | Регистрация в системе |
| `/help` | Список доступных команд |
| `/status` | Состояние текущей игры |
| `/me` | Мои операции в текущей игре |
| `/history [N]` | Последние N завершённых игр |
| `/game <id>` | Детали конкретной игры |
| `/stats [@user]` | Статистика (общая или по игроку) |

### Управление игрой (дилер)

| Команда | Описание |
|---|---|
| `/newgame [байин_руб байин_фишки рибай_руб рибай_фишки]` | Начать новую игру |
| `/endgame` | Завершить игру (все должны быть кэш-аут) |
| `/endgame_force` | Принудительное завершение с расхождением банка |
| `/cancel` | Отменить текущую игру |
| `/transfer_dealer @user` | Передать роль дилера |
| `/undo [N]` | Откатить последние N операций |

### Заявки (требуют подтверждения дилера)

| Команда | Описание |
|---|---|
| `/join` | Запрос на вход в игру |
| `/rebuy` | Запрос на рибай |
| `/cashout <фишки>` | Запрос на выход с указанием количества фишек |

### Прямые команды дилера (без подтверждения)

| Команда | Описание |
|---|---|
| `/dealer_join @user` | Добавить игрока |
| `/dealer_rebuy @user` | Провести рибай |
| `/dealer_cashout @user <фишки>` | Провести кэш-аут |
| `/admin_cancel` | Отменить игру (если дилер неактивен >6ч) |

## Типичный сценарий игры

```
Игрок А: /newgame 1000 1000 500 500
  → Создана игра: байин 1000₽ = 1000 фишек, рибай 500₽ = 500 фишек

Игрок Б: /join
  → Заявка отправлена дилеру
  → Дилер А подтверждает [✅] → 1000₽ внесено в банк

Игрок Б: /rebuy
  → Дилер А подтверждает [✅] → ещё 500₽ в банке

Игрок Б: /cashout 1500
  → Дилер А подтверждает [✅] → 1500₽ выплачено

Игрок А: /endgame
  → Рассчитан план переводов между игроками
```

## Алгоритм расчётов

Расчёт планов взаимозачётов работает в три шага:

1. **Точные совпадения** — если долг одного игрока точно совпадает с прибылью другого, выполняется прямой перевод.
2. **Жадный алгоритм** — оставшиеся долги и прибыли сортируются по убыванию и поочерёдно сопоставляются.
3. **Оптимизация** — если у кого-то получается более 2 исходящих переводов, алгоритм ищет комбинацию кредиторов с совпадающей суммой для консолидации.

При принудительном завершении (`/endgame_force`) расхождение банка распределяется пропорционально между кредиторами или должниками.
